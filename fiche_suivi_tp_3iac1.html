Créer la structure du rôle avec ansible-galaxy role init, puis remplir defaults/main.yml (variables par défaut), tasks/main.yml (créer dossiers + appeler le template), handlers/main.yml (recharger configuration notifié par la tâche template). Appeler le rôle depuis use-role.yml.

Fichiers du dépôt
📄ansible/roles/app-config/defaults/main.ymlVariables par défaut du rôle : app_name, app_version, app_environment, app_port, app_config_dir… La priorité la plus basse — surchargeable depuis le playbook.

TP FINAL TP Final — Terraform génère, Ansible consomme 14:15 – 15:30 Slide 27 ▶

Terraform génère servers/server-N.json et l'inventaire ansible/inventories/generated.ini via un templatefile() HCL. Ansible le consomme avec -i inventories/generated.ini. On teste le ping, puis on lance deploy.yml qui génère des configs dans output/. Optionnel : lancer le tout via scripts/deploy.sh.

Fichiers du dépôt
📄terraform/tp-final/main.tfCœur du TP final : resource local_file "server_info" (N serveurs simulés) + resource local_file "ansible_inventory" qui utilise templatefile() pour générer le INI Ansible.
🗂terraform/tp-final/templates/inventory.tplTemplate HCL qui génère le format INI Ansible avec une boucle %{ for ip in servers }. Syntaxe HCL — différente de Jinja2.
📋ansible/inventories/generated.ini.exampleExemple du fichier produit par Terraform. Permet aux étudiants de visualiser le format attendu avant de lancer terraform apply.
📄ansible/playbooks/deploy.ymlPlaybook final : affiche les infos de chaque hôte, crée les dossiers app/logs/config, génère nginx.conf.j2 et app-config.json.j2 pour chaque serveur simulé.
🗂ansible/templates/nginx.conf.j2Template nginx avec bloc conditionnel {% if deploy_environment == 'production' %}. Illustre la différence de rendu entre environnements.
📜scripts/deploy.shOrchestre les 3 étapes en séquence : terraform init+apply, ansible ping, ansible-playbook deploy.yml. Avec affichage soigné et gestion d'erreur set -e.

  • host_key_checking = False en lab uniquement
